# V50 — Replacement uses its own source animation

## Problem fixed
The previous exact-source replacement could visually swap the part, but the replacement container still followed bounds generated by the old character part animation. That could make it look like the original animation was still controlling the swapped head.

Also, the exact Annoyed replacement player was rendered at one fixed source frame instead of being driven by the editor playhead.

## Changes
- Applying an exact-source replacement now sets the original selected part to:
  - `visible: false` after the replacement is READY
  - `animate: false` immediately, so the old Head/Face timeline no longer drives the replacement placement
- While the replacement is loading, the original part remains visible but frozen rather than continuing the old animation.
- The Annoyed source-symbol player now listens to editor playhead seek messages.
- Exact Annoyed replacements now animate from the Annoyed source timeline at 30 FPS.
- The Annoyed Head uses source frames **34–174** and loops inside that source range so it does not enter the later `_off` section of `lib.Head`.
- Timeline scrubbing also seeks the replacement source symbol.
- Clearing a replacement restores the original part to `visible: true` and `animate: true`.

## Expected result
Select `Head / Face` → apply `Annoyed Head — Exact Source` → original head freezes while loading → exact Annoyed head becomes visible → pressing Play animates the replacement from Annoyed.zip, not the Men Talk head timeline.
